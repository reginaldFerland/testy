# Testy 1.0 validation

## Latest regression coverage

- **Process cleanup:** group-signaling errors cannot skip ownership-marker cleanup, escalation performs full cleanup, and closed output pipes cannot crash the independent supervisor during teardown. Each owned descendant receives a termination attempt even if another attempt fails. Real C# tests launch a detached Node child under the collector and confirm cleanup after normal completion, cancellation, and extension-host death. Controlled cases cover EPERM and EPIPE. This resolves the real child leak behind the previously observed macOS cancellation diagnostic.
- **Discovery failure:** successful empty projects remain valid; failed discovery exits and explicit error nodes reject before inventory replacement. A regression collects real coverage, injects discovery failures with exits 0 and 2, checks unchanged inventory and traces, then verifies successful recovery.
- **Runtime identities:** rows are attributed by native IDs, canonical source paths, and unambiguous type/method metadata. A failed row from file B reruns B. Unresolved rows appear under **Unmapped runtime tests** and use project fallback, honoring file/test exclusions. Unselectable runtime exclusions report an error before execution. Container runs avoid duplicate project execution, summaries count actual executed files, and later file attribution removes the old project placeholder. Unusual provider streams use controlled MTP peers; editor container lifecycle has a controlled UI regression.
- **Discovery responsiveness:** per-run path caches, indexed ownership, a source set for portable-symbol fallback, and bounded yielding remove repeated per-case filesystem searches. Large discovery cancellation is independently tested.
- **Queued cancellation:** queued manual jobs settle immediately, release their cancellation registrations, preserve FIFO ordering, retain automatic changes, and leave the active manual run untouched.

## Performance

The following probes ran sequentially after the initial integration and source-host checks completed. They measure the actual implementation; synthetic tree probes mock VS Code objects. The real MTP workloads include engine, build, discovery, execution, and persistence costs, excluding debounce and editor rendering.

| Workload | Observation |
| --- | --- |
| Real 20,001-case MTP baseline without collection | 3.44 s; five realpath calls for the shared test source; largest 1 ms timer gap **23.2 ms**, versus roughly **204 ms** and 20,004 calls in the review reproduction. |
| 20,000-case inventory construction | 3.32 ms; one source-path lookup; largest timer gap 1.22 ms. |
| 100,000-case inventory construction | 14.2 ms; one source-path lookup; largest timer gap 2.08 ms, versus roughly 809 ms before. |
| 1,000 runtime rows across 50 files, missing paths supplied | 1.86 ms; 156 filesystem attempts; all owners correct. The review's repeated file search took 442 ms and 51,002 attempts on its missing-path workload. |
| Same runtime rows without source locations | 2.00 ms; all owners correct using method metadata. |
| Real 1,200-case attribution baseline / 20 affected cases / batched run-all | **25.3 s / 3.21 s / 6.58 s**; the affected run writes **one trace**. |
| 100,000-case tree rediscovery with unchanged content | 3.74 ms and zero child replacements; initial construction's largest timer gap 4.26 ms. |
| Live coverage with 3 million source memberships | Synchronous invalidation 2.09 ms; asynchronous delta's largest timer gap 1.91 ms. |
| 20,000 located results through the real transport | 124 ms total; largest timer gap 12.0 ms. |
| 64 MiB process output with an 8 MiB retained tail | 92.7 ms total; largest timer gap 6.82 ms. |

The 1,200-case workload contains a shared production library, three test projects, and 60 test files. Its cache occupied 1.16 MiB. Peak sampled Node heap/RSS were 25.0/140.7 MiB; RSS includes the coverage worker, while these figures exclude separate supervisor, .NET, and collector processes. Initial attribution still pays for per-file runner/collector startup; later affected runs reuse preparation within each project. These are host observations for short generated tests, not latency guarantees for a particular production suite.

## Boundaries

Discovery is scoped to opened workspace folders. Referenced external projects can be built as dependencies; their tests are not discovered. A build failure stops the entire batch.

Native Windows execution was not available locally and remains a CI check. The existing controlled Windows owner/path checks pass in the unit suite. The changed POSIX teardown is exercised on macOS and Linux, with real collector lifecycle integration on macOS. Windows ownership uses the bundled Job Object helper; POSIX ownership combines a process group, inherited nonce, and independent supervisor.

Programs that deliberately remove the ownership marker and detach, or delegate work to an external service, must manage that work's lifetime. Changes to databases, services, environment variables, and unwatched data require a full refresh. Compiler-only generated coverage-exclusion metadata requires run-all mode, as documented in the README.

## Reproduce

```sh
npm ci
npm test
npm run test:integration
npm run test:extension
npm run benchmark
npm run benchmark:responsiveness
node test/performance/cache-and-results.cjs
node test/performance/cache-membership.cjs
node test/performance/editor.cjs
node test/performance/live-updates.cjs
node test/performance/discovery.cjs
npm run package
```

Set `TESTY_COVERAGE_TOOL` to an existing collector executable to avoid repeated installation in temporary test workspaces. Set `TESTY_VSCODE_PATH` to reuse a VS Code installation. To test packaged files, extract the VSIX, set `TESTY_EXTENSION_PATH` to its `extension` directory, and run `npm run test:extension`.
