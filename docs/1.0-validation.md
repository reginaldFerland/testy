# Testy 1.0 validation

Review remediation was validated on macOS arm64 with .NET SDK 10.0.400, Node 22.23.1, and dotnet-coverage 18.1.0. The same unit and integration suites also passed in a Linux arm64 container using the .NET 10.0.400 SDK image and a separate npm installation.

| Check | Evidence |
| --- | --- |
| Build and unit checks | TypeScript, bundled .NET helper, ESLint, and 34 unit tests. |
| Real MTP execution | 12 integration tests, covering the original false-green/missed-test reproductions, empty coverage, initialization failure, manual runs, and retained coverage. |
| Frameworks | MSTest 4.3.3 / MTP 2.3.3; xUnit v3 3.2.0 with its MTP v2 package; NUnit 4.4.0 / adapter 6.3.0. Each performs a passing baseline followed by affected-file selection and failing cases. |
| Project and lifecycle edges | Binary references; source files linked from outside the workspace; `net10.0` and `net10.0-windows` targets with separate identities; changing workspace roots; an unsupported nested SDK selection; baseline checkpoints and cancellation/resume. |
| State and transport edges | Repeated terminal IDs, explicit superseded retries, inconsistent failure exits, runtime-only IDs, directory events, corrupt/concurrently written caches, collector installation cancellation, output mutation, symlinks/cycles, and owned process teardown. |
| Collector installation | Actual first-use installation into staging, atomic rename, and successful invocation of the relocated executable. Fake installer tests cover interrupted and concurrent installation. |
| Editor behavior | A VS Code host scenario covers startup, saves, failures, retained coverage, pause/resume, refresh, run-all mode, collection disabled, external edits, and generated-file exclusion. |
| Packaged host | The extracted final VSIX passed the same VS Code scenario (22 seconds). |
| Packaging | The final VSIX includes JavaScript dependencies, the portable analyzer/runtime files, icons, and notices. Source, fixtures, temporary tools, and CI files are excluded. |

Windows cancellation is exercised with a controlled `taskkill` transport test, including waiting for completion. Native Windows execution has **not** been run locally. The repository's GitHub Actions matrix runs unit/integration checks and packaging on Ubuntu, macOS, and Windows; that remote workflow still needs to run. The Linux process test runs with a container init process to reap orphaned descendants.

## Measured performance

A reproducible generated C# workload has four projects (one shared library and three test projects), 60 test files, and 1,200 MSTest cases. Each file exercises its own production implementation and a shared dependency. Measurements include builds, discovery, source analysis, coverage, and persistence; they exclude editor debounce.

| macOS arm64 measurement | Result |
| --- | ---: |
| Initial per-file attribution baseline | 23.0 s |
| One production method edit: 20 affected cases | 2.5 s |
| Batched run-all mode: all 1,200 cases | 6.2 s |
| Persisted attribution cache after affected run | 451 KiB |
| Peak sampled Node heap / RSS | 27.2 / 127.6 MiB |

This is a generated workload of short tests, not a benchmark of a particular production repository. Node memory excludes child .NET/collector processes. The first baseline still pays for one MTP/collector process per file; prepared outputs and instrumentation are reused per project. Run-all and collection-disabled modes batch by project. A slow real test suite will have different timings.

A separate synthetic coverage workload represents 100 test files × 200 sources × 100 lines (2 million dense line records). Sharing line geometry and storing positive hits reduced serialized data from the review's 41 MiB to 1.39 MiB. First aggregation measured 0.66 ms, versus the review's 23–31 ms; serialization measured 1.63 ms, versus 81 ms. Cached aggregation returns the existing result. An indexed 20-project/5,000-source lookup averaged 0.13 µs in a tight loop; this is an isolated lookup measurement, not save-to-feedback latency.

External databases, services, environment variables, unwatched data, and unobserved runtime behavior remain outside source-based impact tracking. Use a full refresh for those changes. Unsupported/ambiguous source locations retain conservative selection.

## Reproduce

```sh
npm ci
npm test
npm run test:integration
npm run benchmark
npm run package
```

Set `TESTY_COVERAGE_TOOL` to an existing collector executable to avoid repeated installation in temporary test workspaces. Set `TESTY_VSCODE_PATH` to a VS Code executable to reuse an installation. To test packaged files, extract the VSIX and set `TESTY_EXTENSION_PATH` to its `extension` directory, then run `npm run test:extension`.
