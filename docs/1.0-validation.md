POSIX ownership uses an independent runtime process and a control pipe that closes when the extension host dies. It terminates the owned group and inherited-marker descendants before completion; the supervisor also handles cancellation escalation. Windows cancellation uses a bundled Job Object owner with suspended process creation, kill-on-close, and a cancellation/EOF control channel. Controlled transport tests exercise owner cancellation and waiting for a forced `taskkill` fallback. The cross-platform ownership tests are enabled on Windows as well. Native Windows execution has **not** been run locally. The repository's GitHub Actions matrix runs unit/integration checks and packaging on Ubuntu, macOS, and Windows; that remote workflow still needs to run. The Linux process test runs with a container init process to reap orphaned descendants.

## Measured performance

A reproducible generated C# workload has four projects (one shared library and three test projects), 60 test files, and 1,200 MSTest cases. Each file exercises its own production implementation and a shared dependency. The final fifth-review measurements were taken after the other validation jobs finished. They include builds, discovery, source analysis, coverage, ownership supervision, and persistence; they exclude editor debounce.

| macOS arm64 measurement | Result |
| --- | ---: |
| Initial per-file attribution baseline | 25.6 s |
| One production method edit: 20 affected cases | 3.3 s |
| Batched run-all mode: all 1,200 cases | 6.7 s |
| Persisted attribution cache after affected run | 1.16 MiB |
| Peak sampled Node heap / RSS | 24.2 / 140.1 MiB |

This is a generated workload of short tests, not a benchmark of a particular production repository. Node RSS includes the coverage worker; the sampled main-thread heap excludes its heap. Both exclude separate supervisor, .NET and collector processes. The first baseline still pays for one MTP/collector process per file; prepared outputs and instrumentation are reused per project. Run-all and collection-disabled modes batch by project. A slow real test suite will have different timings.

A separate synthetic coverage workload represents 100 test files × 200 sources × 100 lines (2 million dense line records). Sharing line geometry and storing positive hits reduced serialized data from the review's 41 MiB to 1.39 MiB. First aggregation measured 2.58 ms, versus the initial review's 23–31 ms; serialization measured 1.63 ms, versus 81 ms. Cached aggregation returns the existing result. An indexed 20-project/5,000-source lookup averaged 0.14 µs in a tight loop; this is an isolated lookup measurement, not save-to-feedback latency.

The [second review remediation record](review2-remediation.md) includes before/after report parsing, identity indexing, output restoration and UI publication measurements. A 2.9 MB report took 177–223 ms in the parser worker while the main thread continued servicing a 5 ms timer (maximum observed gap 5.8 ms). Cached native-ID selection over 50,000 cases/100 files took 25.6 ms, versus 2.61 seconds before. Unchanged output restoration took 9.5–10.4 ms per 1,000 files, versus about 20 ms. The unchanged-publication probe emits 5,000 objects instead of 500,000 across 100 callbacks. Those measurements describe the second-review state. The latest cache restore, live result classification and output-restoration measurements are in the third-review record, with their workload boundaries. Fourth-review checkpoint and watcher measurements are in the fourth-review record. Fifth-review editor aggregation and unchanged manual graph measurements are in the fifth-review record.

External databases, services, environment variables, unwatched data, and unobserved runtime behavior remain outside source-based impact tracking. Use a full refresh for those changes. Unsupported/ambiguous source locations retain conservative selection.

## Reproduce

```sh
npm ci
npm test
npm run test:integration
npm run benchmark
npm run benchmark:responsiveness
node test/performance/cache-and-results.cjs
node test/performance/cache-membership.cjs
node test/performance/editor.cjs
npm run package
```

Set `TESTY_COVERAGE_TOOL` to an existing collector executable to avoid repeated installation in temporary test workspaces. Set `TESTY_VSCODE_PATH` to a VS Code executable to reuse an installation. To test packaged files, extract the VSIX and set `TESTY_EXTENSION_PATH` to its `extension` directory, then run `npm run test:extension`.
