## Latest regression coverage

- **Skipped instrumentation:** an unchanged assembly after a successful collector command retains its runtime project dependency. A real symbol-less library sharing a source with an instrumented library selects both callers after a change, leaves the unrelated test out, and detects the same failure as run-all.
- **Project eligibility:** converting a test project into a library removes discovered and runtime-only rows, coverage, and baseline checkpoints before a later build failure. The removal survives cache restoration. Removing a workspace test folder stops executing its tests while preserving its dependency build role; adding it back rediscovers the tests.
- **Startup and failed-run recovery:** inherited SDK candidates are observable before SDK validation. Fixing an invalid initial pin recovers testing, and candidate creation/deletion during execution rejects obsolete checkpoints. Newly evaluated external inputs are watched before build/discovery succeeds; a real VS Code scenario recovers by editing only an external file after a syntax-error build.
- **Saved encodings:** UTF-8 and UTF-16 BOMs in either byte order use the same bounded byte prefix. Tests cover aliases in generated inputs, odd trailing code units, deletion, header removal, the real editor save handler, and timestamped UTF-16 build outputs that must not repeatedly abort the baseline.
- **Manual result retention:** the actual compiled selection callback preserves a failed runtime row when an ordinary sibling is selected, and a later terminal result updates that row normally.
- **Portable analysis:** Linux validation exposed platform-specific Roslyn binaries copied from the macOS SDK. The analyzer now uses pinned portable NuGet assemblies. Unit checks reject native managed images, and Linux runs the macOS-built analyzer successfully with narrow affected selection.

## Previously established regression coverage

- **Runtime module dependencies:** real `Assembly.LoadFile`, in-memory assembly loads, and managed child processes retain dependencies on workspace projects when execution bypasses the instrumented private output. A new source in such a project selects its calling tests even without `ProjectReference`. The observer preserves existing startup hooks, checks completed reports, persists module edges, and falls back conservatively on missing or malformed observations while retaining line coverage.
- **Generated headers:** only declarations in leading comments classify a C# source as generated. String literals and explanatory comments containing a marker remain ordinary tracked code. A real editor save and the actual save handler both exercise this distinction.
- **Compiler configuration:** inherited `.editorconfig`, global analyzer configuration, and configured rulesets participate in input ownership, triggers, and version checks. Creation or deletion during execution prevents obsolete baseline checkpoints. Ancestor configuration candidates use nonrecursive external watchers and do not make unrelated external source saves eligible.
- **Runtime inventory and manual selection:** a complete file-by-file baseline retires disappeared unmapped rows, including after cancellation and resume. Partial checkpoints retain them. Selection resolves runtime fallback and exclusions before batching, avoiding duplicate execution while keeping file-level coverage contributions.
- **Process cleanup:** group-signaling errors cannot skip ownership-marker cleanup, escalation performs full cleanup, and closed output pipes cannot crash the independent supervisor during teardown. Each owned descendant receives a termination attempt even if another attempt fails. Real C# tests launch a detached Node child under the collector and confirm cleanup after normal completion, cancellation, and extension-host death. Controlled cases cover EPERM and EPIPE. This resolves the real child leak behind the previously observed macOS cancellation diagnostic.
- **Discovery failure:** successful empty projects remain valid; failed discovery exits and explicit error nodes reject before inventory replacement. A regression collects real coverage, injects discovery failures with exits 0 and 2, checks unchanged inventory and traces, then verifies successful recovery.
- **Runtime identities:** rows are attributed by native IDs, canonical source paths, and unambiguous type/method metadata. A failed row from file B reruns B. Unresolved rows appear under **Unmapped runtime tests** and use project fallback, honoring file/test exclusions. Unselectable runtime exclusions report an error before execution. Container runs avoid duplicate project execution, summaries count actual executed files, and later file attribution removes the old project placeholder. Unusual provider streams use controlled MTP peers; editor container lifecycle has a controlled UI regression.
- **Discovery responsiveness:** per-run path caches, indexed ownership, a source set for portable-symbol fallback, and bounded yielding remove repeated per-case filesystem searches. Large discovery cancellation is independently tested.
- **Queued cancellation:** queued manual jobs settle immediately, release their cancellation registrations, preserve FIFO ordering, retain automatic changes, and leave the active manual run untouched.

## Performance

The current 1,200-test benchmark ran after the integration and editor suites finished. Across three test projects and 60 test files, the baseline took **31.5 seconds**, a source edit selected **20 tests in 3.35 seconds**, and batched run-all took **6.97 seconds**. The affected run detected all 20 expected failures and persisted exactly **one trace**. Cache size was **1.43 MiB**; peak sampled Node heap/RSS were **26.3/145.5 MiB**, excluding separate supervisor, .NET, and collector processes. Timings include engine/build/execution work and exclude debounce and editor rendering. The module observer preserves narrow selection; the initial per-file attribution cost remains significant.

The following detailed responsiveness measurements are historical results from the preceding commit, `498b35d`. They were not rerun for these fixes. Synthetic tree probes mock VS Code objects. Real MTP workloads include engine, build, discovery, execution, and persistence costs, excluding debounce and editor rendering.

## Boundaries

Discovery is scoped to opened workspace folders. Referenced external projects can be built as dependencies; their tests are not discovered. A build failure stops the entire batch.

Native Windows execution was not available locally and remains a CI check. The existing controlled Windows owner/path checks pass in the unit suite. The changed POSIX teardown is exercised on macOS and Linux, with real collector lifecycle integration on macOS. Windows ownership uses the bundled Job Object helper; POSIX ownership combines a process group, inherited nonce, and independent supervisor.

Programs that deliberately remove the ownership marker and detach, or delegate work to an external service, must manage that work's lifetime. Changes to databases, services, environment variables, and unwatched data require a full refresh. Compiler-only generated coverage-exclusion metadata requires run-all mode, as documented in the README.

Module observation covers the test host and child .NET processes that inherit and support the startup hook. Children that suppress that hook and execution delegated to an external service require run-all mode when they execute workspace code.

## Reproduce

```sh
npm ci
npm test
npm run test:integration
npm run test:extension
npm run benchmark
npm run benchmark:responsiveness
node test/performance/cache-and-results.cjs
node test/performance/cache-membership.cjs
node test/performance/editor.cjs
node test/performance/live-updates.cjs
node test/performance/discovery.cjs
npm run package
```

Set `TESTY_COVERAGE_TOOL` to an existing collector executable to avoid repeated installation in temporary test workspaces. Set `TESTY_VSCODE_PATH` to reuse a VS Code installation. To test packaged files, extract the VSIX, set `TESTY_EXTENSION_PATH` to its `extension` directory, and run `npm run test:extension`.
