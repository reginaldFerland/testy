# Testy 1.0 validation

Validated locally on macOS arm64 with .NET SDK 10.0.400, MSTest 4.3.3 / MTP 2.3.3, and dotnet-coverage 18.1.0.

| Check | Evidence |
| --- | --- |
| TypeScript, .NET helper, and lint | `npm test` builds both components, runs ESLint, and passes 20 unit tests. |
| Impact analysis and real execution | Two integration tests cover method-body selection, declaration/constant fallback, transitive code use, parameterized cases, failure details, new files, retained coverage, partial manual runs, and prompt cancellation of a long-running test. |
| Actual VS Code behavior | The extension-host scenario exercises startup, editor saves, failures, pause/resume, full refresh, run-all mode, coverage disabled, filesystem changes, and generated-file exclusion. |
| Packaged extension | The VSIX was extracted and used as the extension development directory in an isolated VS Code host; the same scenario passed against the packaged files. |
| Artifact contents | Verified version 1.0.0, JavaScript dependencies, portable analyzer assemblies and runtime configuration, gutter icons, and license notices. Source, fixtures, and backend build directories are excluded. |

The three-case fixture measured approximately 2.5–2.7 seconds for the initial baseline and 1 second for a subsequent affected run (two cases in one test file). This includes build, discovery, source analysis, test execution, and coverage collection, but excludes editor debounce. It is a small-fixture measurement, not a large-suite benchmark.

Windows, Linux, and other MTP frameworks have not been exercised in this environment. The first baseline runs each test file separately to establish attribution, so large suites have additional startup overhead. Runtime tracing cannot infer dependencies on external services or unwatched data; a full refresh remains necessary for those changes.

## Reproduce

```sh
npm ci
npm test
npm run test:integration
npm run package
```

For host testing, set `TESTY_VSCODE_PATH` to a VS Code executable if reusing an installation, `TESTY_COVERAGE_TOOL` to an existing collector if desired, and `TESTY_EXTENSION_PATH` to the extracted VSIX's `extension` directory to test the package. Then run `npm run test:extension`.
