# Testy 1.0

## Product contract

Testy gives fast, automatic C# test and coverage feedback. It owns a VS Code TestController and runs .NET 10+ processes directly using Microsoft.Testing.Platform (MTP); C# Dev Kit and VSTest are not required.

- On workspace open: build, discover, and establish a baseline for all C# tests.
- By default, react to editor saves. File-system changes are an optional trigger. Exclude generated and build output files.
- Select affected **test files** by tracing which source code their tests execute. An explicit `all` mode is available.
- Request cancellation immediately on new changes, wait for owned processes to exit, and start once the debounce period has elapsed. Preserve the union of pending changes across cancellation.
- Never cancel manually initiated runs automatically.
- If impact information is unknown or incomplete, run the affected project and dependent test projects conservatively.
- Coverage is configurable and enabled by default. Retain unaffected test-file coverage; invalidate stale contributions before replacing them.
- Refresh builds, rediscovers tests, and runs a complete baseline.
- Show progress, failure details, stale state, coverage, and a pause/resume control without notification spam.

## Execution approach

Discover test identities and source locations through MTP's documented JSON-RPC protocol. Execute MTP applications with `dotnet`, grouping by test file, and receive structured progress and results over the same protocol. Collect a separate coverage contribution per test file, enabling both reverse dependency lookup and replacement of coverage without losing contributions from other files. Build once per change batch, then run already-built assemblies. Instrument isolated copies of outputs so cancellation cannot leave user binaries modified.

A Roslyn helper fingerprints declarations after removing ordinary method/accessor bodies. Changed declarations, constants, initializers, attributes, and directives force project fallback; missing or invalid analysis does the same. This covers compile-time dependencies that executable coverage cannot observe. The fingerprints advance only after a complete automatic run or full refresh, never a partial manual run.

Target .NET 10+ and MTP exclusively. Unsupported configurations report an actionable error rather than silently selecting no tests. Discovery and filtered execution use structured messages without an additional result-logger package.

## Correctness invariants

1. An incomplete/cancelled run never commits new dependency or coverage data.
2. A cancellation never loses a previously pending source change.
3. A file with no trustworthy mapping triggers a conservative fallback, never a successful empty run.
4. Test identity includes project and target framework. File grouping includes all cases and methods located in that file.
5. Deleting tests removes their coverage contributions. Editing source makes previous coverage stale until a valid replacement exists.
6. A replacement run never overlaps the cancelled automatic run. Manual runs cannot be cancelled by a save.
7. Builds and tests execute only in a trusted workspace. Commands are spawned as argument arrays without a shell.

## Verification

- Unit tests: selection and dependency fallback, retained coverage replacement, configuration validation, generated-file exclusion, scheduler cancellation/debounce races.
- Real .NET fixture: independent code/test files, shared transitive dependencies, parameterized tests, a failing test, changed/new/deleted code, and coverage attribution. Assert executed identities and report contents, not only command success.
- Extension-host tests: discovery tree, manual/automatic runs, refresh, pause, settings, saved-file triggers, coverage publishing, teardown.
- Release: compile, lint, test, package 1.0.0 VSIX, inspect packaged helper/runtime files, and smoke-test the packaged extension.
